## Interpretation

- Schema validity proved only structural and internal semantic consistency.
- The package path remained caller-controlled.
- CI, scope, Inspector identity, source observation, and execution claims were not minted by official adapters.
- Deterministic projection faithfully amplified the unverified claims; determinism did not establish factual truth.
- The successor protocol must therefore remove raw-package official completion rather than add more caller-writable provenance fields.

## v1.12 re-verification regression discovered during closure

The initial v1.12 implementation removed raw-package input from `complete_review`, but the public `verify_completed_review` path still accepted a caller directory, package object, and Head source. Because package provenance was exact-type only and `VerifiedLivePullRequestHead` was directly constructible, a caller could copy a genuine package value, provide a self-consistent persisted bundle and fake Head source, and mint a second `VerifiedReviewCompletion`.

The root-complete repair makes package issuance and completion re-verification process-local. The official assembler registers the exact package object it minted. Public re-verification accepts only the original genuine completion, validates its bound directory and bound internal Head source, and returns the same object. Persisted artifacts remain diagnostic outputs but cannot reconstruct authority across processes.
